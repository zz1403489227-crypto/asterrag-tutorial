# 检索增补篇：原理与流程重写记录

## 为什么重写

用户指出首版像琐碎的源码检索报告：过多交代限制，原理、索引和图谱过程讲得不足。首版的文件与源码检查通过，并不意味着教学质量合格。本轮重写五章，而不是只删去几个谨慎措辞。

## 结构变化

| 章 | 重写后的核心过程 |
|---|---|
| 21 | 全量查找为什么贵 → 索引的提前组织 → 邻近图 → 层次 → 插入选邻居 → 查询保留候选 → 参数预算 → 项目应用 |
| 22 | 专名与语义线索 → 倒排列表 → 中文分词 → TF 饱和 → IDF → 长度归一化 → 公式 → 查询 → 双路互补 |
| 23 | 分散事实 → 实体关系 → 抽取与描述 → 合并 → 来源 → 图与向量结合 → local/global/hybrid → 原文与回答 |
| 24 | 明确问题范围 → 多路候选 → 去重 → RRF 计算 → 精排 → 预算与证据 → 上下文与回答 |
| 25 | 固定 RAG → 决策执行循环 → 知识工具 → 一轮信息流 → 内外模型分工 → 补查 → 记忆与业务能力 → 项目主线 |

教学例子统一为林辰、远山科技、星河项目、周宁与差旅制度。HNSW 距离、BM25 词频数值、RRF 名次均为解释机制的自编例子。

## 人工审读

- HNSW 的随机层级是算法层次，不是业务知识库分类；建图和查询分开解释。
- HNSW 搜索宽度与最终返回条数分开，使用逐步候选变化例子。
- BM25 在公式前先解释三个因素，分块粒度对应 ES 被评分文档。
- 图谱原理在 Java 接口前展开；local 从实体进入，global 从关系主题进入，hybrid 组合两路，不混作外层三路 RRF。
- 图谱保留语义联系和来源，原文中的条件由生成阶段使用，不把图数据库描述成自行执行审批规则的业务系统。
- Agent 工具结果成为后续决策输入，内部知识工具合成与外层整体任务处理分别说明。
- 配置名、PG / Milvus 差异、来源过滤、无分降级等细节迁入附录 D；既有 19 条源码映射保留。
