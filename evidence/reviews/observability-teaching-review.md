- OpenTelemetry 的信号、上下文传播、日志关联与采样仅作为概念核对，正文就近链接官方资料；不声称项目已引入 OpenTelemetry。
- Agent Trace 描述可观察调用、工具结果和状态，不要求或承诺取得模型隐藏思维链。
- Span 的执行成功、工具业务成功、任务质量成功，以及评测裁判成功分开讲述。

## 教学审读

- 三章顺序为留过程 → 查原因 → 监控与评测闭环，贯穿同一手机参数案例，不按源码文件分章。
- 树图区分固定 RAG 与外层 Agent；跨会话身份不会被合并成一条无限长 Trace。
- 逐层诊断包含查询、原始召回、后处理、实际材料、最终回答；明确块命中与整篇文档命中的差别。
- 并行检索采用最大完成时间而非各分支相加；区分首内容和最终完成。
- 区分 Trace 记录缺失与业务没有发生；观测能支持假设但不能自动证明因果。
- 回放不默认执行有副作用工具；超时不推导为操作从未成功。
- 代表性样本、难例及是否参与调优是不同维度；无真值线索不冒充真实准确率。
- 采样后的失败案例比例不冒充总体失败率；关键指标不把唯一用户/Trace ID 作为普通标签。
