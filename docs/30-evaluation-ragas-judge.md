# 第 30 章：RAGAS——模型裁判究竟怎样判卷

上一章解决了“找到了哪个文档”。这一章解决“材料里有什么、回答用了什么”。这是 RAG 质量判断最核心的一步。

先记住一件事：**模型负责把自然语言关系转成可计算的判断，公式负责把判断汇成分数。**不是所有指标都让模型直接拍一个 0～100 分。

## 30.1 四份文本之间的五种比较

回到 S2-01，问题 Q 是尺寸和刷新率，参考答案 R 包含 6.73 英寸与动态 1–120Hz。C 是检索文本，A 是系统回答。

| 指标 | 主要比较关系 | 直白问题 |
|---|---|---|
| context_recall | 参考 R → 材料 C | 标准答案需要的事实找全了吗？ |
| context_precision | 各段 C 与 Q、R | 有用材料有没有排在前面？ |
| faithfulness | 回答 A → 材料 C | 回答的每个说法都有材料支持吗？ |
| answer_correctness | 回答 A ↔ 参考 R | 答案在事实和完整性上对吗？ |
| answer_relevancy | 回答 A → 反推问题 ↔ Q | 回答到底在解决哪个问题？ |

这是五种关系，不是五个同义词。项目通过 RAGAS 调用它们，传入的核心字段就是 user_input、response、retrieved_contexts、reference。

下面的原理以 RAGAS 官方 v0.2.14 文档和源码为解释参考。项目封装使用这些指标的传统接口，但仓库说明不能证明某次外部环境安装了哪一个精确版本；具体参数备查放在附录 E。

## 30.2 Faithfulness：回答里的话，材料支持几句

为了演算，假设检索材料明确包含：尺寸 6.73 英寸，刷新率动态 1–120Hz。系统却回答：

```text
屏幕为 6.73 英寸，支持动态 1–120Hz，并且支持裸眼 3D。
```

最后一句是故意加入的无依据说法。裁判可以把回答拆成三个事实主张（claim）：

| 回答主张 | 材料是否支持 |
|---|---|
| 尺寸为 6.73 英寸 | 支持 |
| 刷新率为动态 1–120Hz | 支持 |
| 支持裸眼 3D | 不支持 |

在这一教学拆分下：

```text
Faithfulness = 被材料支持的回答主张数 / 回答主张总数
             = 2/3
```

关键动作是“拆主张”和“检查能否推出”。它允许换一种说法表达同一事实，不要求答案逐字抄原文。实际判分时，主张拆分与支持判断由裁判完成，未必每次恰好拆成我们演算的三项。[RAGAS Faithfulness 原理](https://docs.ragas.io/en/v0.2.14/concepts/metrics/available_metrics/faithfulness/)。

忠实不等于正确：如果材料本身过期，模型忠实复述也可能不符合最新事实；如果材料只有尺寸，模型只回答尺寸，它可能很忠实，却没完整回应问题。Faithfulness 不能独自代表回答质量。

## 30.3 Context Recall：标准答案需要的事实，材料覆盖几项

现在不看系统说了什么，而是看参考答案需要什么。S2-01 有两个必答事实：尺寸与刷新率。

假设返回的是同一份商品文档里的一个短片段，只写着尺寸 6.73 英寸，没有刷新率信息。按这两个主张演算：

```text
Context Recall = 材料能够支持的参考主张数 / 参考主张总数
               = 1/2
```

如果两项都在材料里，就是 2/2。这个指标看的是生成前“原料够不够”，不要求系统已经把所有原料写进答案。[RAGAS Context Recall 原理](https://docs.ragas.io/en/v0.2.14/concepts/metrics/available_metrics/context_recall/)。

它与第 29 章的文档 Recall 很不一样：同一个 `PROD_PHONE_004` 命中，文档 Recall 可以是 1；但只拿到尺寸片段时，参考事实覆盖仍可能只有一半。

反方向也值得理解：如果标注文档之外的另一段材料同样准确包含两个事实，文档指标可能不奖励它，事实覆盖却可以很好。这正是两层评估互相补充的价值。

## 30.4 Context Precision：不仅看有用比例，还看顺序

这个名字最容易被讲错。项目采用的传统 context_precision 是一种排序敏感的计算，不只是“有用块数量 / 总块数量”。

裁判先判断每个块是否有助于参考答案，得到相关标记 v，再在相关位置计算累计 Precision 并平均。

假设四个教学片段按顺序是：尺寸、配件、刷新率、包装。有用性标记为 [1,0,1,0]：

| 位置 k | 有用 v_k | 到此为止有用块数 | P@k | 计入的 P@k × v_k |
|---:|---:|---:|---:|---:|
| 1 | 1 | 1 | 1/1 | 1 |
| 2 | 0 | 1 | 1/2 | 0 |
| 3 | 1 | 2 | 2/3 | 2/3 |
| 4 | 0 | 2 | 2/4 | 0 |

```text
Context Precision = Σ(P@k × v_k) / 本次返回列表中有用块的数量
                  = (1 + 2/3) / 2
                  ≈ 0.833
```

若仍是这四块，但顺序变成 [配件,包装,尺寸,刷新率]，标记 [0,0,1,1]，则分数变为 (1/3+2/4)/2≈0.417。两种排列的有用块比例都是 2/4，排序分却不同。[RAGAS Context Precision 公式](https://docs.ragas.io/en/v0.2.14/concepts/metrics/available_metrics/context_precision/)。

因此它不仅在意有没有噪声，也在意噪声是否挡在有用材料前面。不过有用块之后追加无用尾巴不一定降低这个排序分，不能把它当作上下文长度或全部 token 浪费的完美衡量。无有用块的情况由具体实现处理，不能手算成除以零。

## 30.5 Answer Correctness：正确事实、错误事实与遗漏

假设参考答案有两项：6.73 英寸、动态 1–120Hz。教学回答是：“6.73 英寸，固定 60Hz。”

对比后可以得到：

- TP：正确匹配的事实，尺寸这一项。
- FP：答案多说或说错的事实，固定 60Hz。
- FN：参考里应有但答案没正确覆盖的事实，动态 1–120Hz。

在 TP=1、FP=1、FN=1 的教学拆分下，事实 F1 为：

```text
F1 = 2TP / (2TP + FP + FN) = 2/4 = 0.5
```

RAGAS v0.2.14 的 AnswerCorrectness 还把这个事实分与答案—参考的语义相似度加权，默认权重是 0.75 和 0.25。假设相似度为 0.8，那么演算总分是 0.75×0.5+0.25×0.8=0.575。这个相似度是人为给定的演算输入，不是我们调用 Embedding 得到的结果。[该版本 AnswerCorrectness 源码](https://github.com/explodinggradients/ragas/blob/v0.2.14/src/ragas/metrics/_answer_correctness.py)。

为什么不只用相似度？“动态 1–120Hz”和“固定 60Hz”都围绕刷新率，词面与语义主题很近，但事实不同。事实比较用来识别这种错误；相似度辅助衡量整体表达接近程度。

参考不完整也会影响判断。如果标准只有尺寸而题目还问刷新率，参考答案本身就漏了需求；如果参考是“应命中商品文档”，更不是同一个事实比较对象。这就是第 27 章先讲出题的原因。

## 30.6 Answer Relevancy：从答案反推它在回答什么

“答得都是真话”仍然可能答非所问。用户问屏幕，系统介绍拍照和充电，这些内容即便都来自材料，也没有解决当前问题。

传统 answer_relevancy 的思路很巧：先让模型只根据回答反向生成可能的问题，再把这些问题与原问题做 Embedding 余弦相似度比较。

```text
回答：“尺寸是 6.73 英寸，动态 1–120Hz。”
   → 反推：“这款手机屏幕多大、刷新率多少？”
   → 与原问题语义接近

回答：“支持高速充电，拍照表现出色。”
   → 反推：“这款手机的充电和影像特点是什么？”
   → 与原问题偏离
```

在普通可回答情形，核心计算是这些相似度的平均；实现还涉及对非承诺性回答的处理。由于基础量是余弦相似度，不应把它严格解释成“正确概率”。它关注切题，不验证答案事实真伪。[RAGAS Response Relevancy 原理](https://docs.ragas.io/en/v0.2.14/concepts/metrics/available_metrics/answer_relevance/)。

项目对部分推理模型把这一指标的 strictness 设为 1。它控制单轮判分中反向问题生成的数量，与后面整套评分重复几轮不是一回事。

## 30.7 为什么模型裁判还要配 Embedding

上面两个算法已经给出答案：Correctness 的语义相似度部分，以及 Relevancy 的反向问题比较，都需要把文本映射为向量并比较。

所以裁判侧也有模型分工：

```text
裁判 LLM：拆事实、判断支持关系、反向生成问题
裁判 Embedding：比较文本语义距离
计算逻辑：计数、F1、排序加权、均值
```

这套 Embedding 服务属于评分器，不是知识库索引本身。不能看到裁判的 Embedding 模型名称，就说产品向量检索使用了它。

## 30.8 项目怎样把这五项真正串起来

作者封装的工作顺序可以缩成：

1. 从录制结果挑出有回答、有材料、有参考，且状态为 success 的题。
2. 将四个文本字段组成 RAGAS 数据集。
3. 创建裁判 LLM、裁判 Embedding 和五个指标对象。
4. 调用 RAGAS，取得每题每项分数。
5. 清理无效分数，汇总为逐题、一级意图、二级意图和总体结果。

第一步是项目采用的统一筛选策略，不是说五种指标在理论上都必须拥有全部四个字段。例如 Faithfulness 的核心并不需要参考答案，但当前封装仍把没有 reference 的记录一起排除。

因此查看一个均值时，要同时知道多少题可评、多少题跳过。低覆盖子集的高分不能自动代表全部输入都表现很好。

## 30.9 重复判卷：减小随机波动，不会修正坏标准

项目支持独立执行 N 轮 RAGAS，再对每题、每指标的有效分数平均。它不是把同一问题重新发给 RAG N 次，而是用同一份录制结果多次判卷。

假设某项三轮分数为 0.6、0.8、1.0，最后该题为 0.8；如果是 0.6、无效、1.0，则有效均值仍是 0.8，不是把无效当 0 后除以 3。

这个办法可以平滑偶然波动，但不能解决系统性偏差：参考答案有误、裁判误解行业术语、用旁路材料替代实际生成材料，重复很多遍也不会自动变正确。

当前封装保留最终逐题均值及轮数等信息，没有把每轮分布与置信区间都作为正式结果输出。因此不要把“取过均值”扩展成“做过显著性检验”。

## 30.10 零分、跳过、裁判失败是三种事

```text
零分：裁判形成了有效判断，认为这项没有做到。
跳过：记录不符合当前可评条件，没有进入判卷。
失败：进入判卷，但模型调用或解析没有得到有效分数。
```

项目在批量判分失败后会尝试回退到其它调用方式，再逐题隔离；全轮都无有效值的指标还会尝试重评，仍失败则保留 None。核心思想是保住其它题的可用结果，而不是用假的零分掩盖评分器故障。

读报告时最好同时看状态分布、可评覆盖和有效分数。比如回答全空时，不能因为某个剩余子集的 Faithfulness 很高，就说整个系统稳定可靠。

## 30.11 五个指标怎样组成一张诊断地图

| 材料与回答的教学情形 | 重点观察 |
|---|---|
| 材料只有尺寸，回答也只有尺寸 | 文档 Hit 可以高；事实 Recall 不足；忠实性可能高 |
| 材料完整，回答漏刷新率 | 事实 Recall 可以高；Correctness/切题完整性需要关注 |
| 材料完整，回答额外编造功能 | Faithfulness 与 Correctness 都可能受影响 |
| 材料混乱，有用块排在最后 | Context Precision 揭示排序问题 |
| 回答正确但不是用户问的内容 | Relevancy 揭示偏题 |

表中“可能”来自指标职责和裁判判断，并不削弱原理：它提醒我们看的是多种互补关系，而不是一组必然同涨同跌的数字。

## 30.12 本章应该怎样讲给面试官

> 我把语义评估分为检索材料与答案两个层面。材料层看参考事实是否覆盖、有用块是否靠前；答案层看每个主张是否受材料支持、与参考事实是否一致，以及是否切题。RAGAS 负责语义判断与公式聚合，项目再做可评样本筛选、重复评分和报告。裁判分是诊断信号，需要结合逐题材料和人工复核解释。

下一章不再增加指标，而是把这些分数用起来：怎样定位问题、比较方案，以及怎样从 RAG 评测进一步设计 Agent 评测。
